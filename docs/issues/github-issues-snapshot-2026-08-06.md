## #75 — GAP-in-expression-position and duplicate IMPLICIT const names produce invalid Rust

State: **OPEN** · Created: 2026-08-05T14:40:00Z · Labels: bug · [View on GitHub](https://github.com/awtoau/awto-renode-rs/issues/75)

Found during full-corpus verification for #64-#68 (\`compile_check.py --ratchet -j8\`, 687 modules, 143 errors remain). Two distinct, generic defect classes — neither is corpus-specific.

## 1. GAP comment substituted into a syntactically-required expression position

When the converter cannot emit an expression, it withholds correctly in *statement* position (a \`/* GAP: ... */\` comment on its own line). But in *expression* position — where a boolean condition, index, or scrutinee is mandatory — the comment is spliced directly into the token stream, leaving invalid syntax. Example, identical shape in \`arm.rs\` and \`sifive_uart.rs\`:

\`\`\`rust
if !/* GAP: base-class call */ {
    return false;
}
\`\`\`

\`!\` has nothing to negate; rustc reports \"expected \`{\`, found keyword \`return\`\" (or similar) at the following line.

Confirmed present (same or a closely related sub-pattern) in ~15 modules: \`arm.rs\`, \`xtensa.rs\`, \`translationcpu.rs\`, \`sparc.rs\`, \`riscv64.rs\`, \`riscv32.rs\`, \`powerpc.rs\`, \`powerpc64.rs\`, \`sifive_uart.rs\`, \`si32_usart.rs\`, \`stm32f7_usart.rs\`, \`usbserialport_s3b.rs\`, \`potato_uart.rs\`, \`picosoc_simpleuart.rs\`, \`uarthubbase.rs\`, \`samd5_uart.rs\`, \`samsungk9nandflash.rs\`, \`renesasda_i2c.rs\`, \`platformlevelinterruptcontroller.rs\`, \`opentitan_platformlevelinterruptcontroller.rs\`, \`nxp_lpuart.rs\`. Some are format-string argument-count mismatches, some are \"expected a pattern, found an expression\" — same underlying cause (a gap marker used where an expression is mandatory), different surface shapes depending on the surrounding grammar production.

**Root cause is in the emitter, not any one peripheral.** When emission of a sub-expression fails inside a position where Rust syntax mandates a real expression (condition, index, scrutinee, macro argument), the fix belongs in the shared expression-emission path: withhold the *enclosing statement/method* (as already done for other unsupported constructs) rather than interpolating the gap comment into the expression slot.

## 2. Duplicate \`const\`/function names within one generated module (E0428)

Different root cause than the already-fixed loop-replicated-register naming class (commit 929e3a1). \`isp1761.rs\` alone has six:

\`\`\`rust
pub const IMPLICIT: u64 = 0x144;
pub const IMPLICIT: u64 = 0x154;
pub const IMPLICIT: u64 = 0x308;
pub const IMPLICIT: u64 = 0x30C;
pub const IMPLICIT: u64 = 0x310;
pub const IMPLICIT: u64 = 0x33C;
\`\`\`

An unnamed/synthesized register-offset or enum-member entity is uniformly named \"IMPLICIT\" with no disambiguation by value or index. Also seen (11 E0428 instances total, 6 modules): \`litesdcard.rs\`/\`litesdcard_csr32.rs\` (\`dma_done_0_provider\`), \`nrf52840_spi.rs\` (\`enable_interrupt_writer\`, \`disable_interrupt_6_writer\`, \`disable_interrupt_writer\`), \`stm32_adc_common.rs\` (\`control_1_provider\`).

Fix belongs wherever unnamed entities get their generated identifier — append the offset/value/index the same way the already-fixed loop-replication naming does.

## Acceptance criteria
- Both classes fixed at the shared emitter/naming layer, not per-file.
- \`compile_check.py --ratchet\` shows zero instances of \"expected \`{\`... found keyword\" from a GAP-in-condition cause, and zero E0428 from duplicate synthesized names.
- \`compile_clean_set.json\` floor grows to include the newly-clean modules (currently 617/687 after #64-#68's fixes; this issue's fix should move it further).

## Evidence
- Full ratchet log: 143 errors / 70 modules remain after #64-#68 closure (commit growing \`compile_clean_set.json\` to 617 lands alongside this issue).
- Direct source inspection: \`arm.rs\` line ~850, \`sifive_uart.rs\` line 142, \`isp1761.rs\` lines 92-100 (see snippets above).

## #74 — Architecture plan proposal: review and disposition

State: **OPEN** · Created: 2026-08-05T14:20:57Z · Labels: decision, research, transpiler · [View on GitHub](https://github.com/awtoau/awto-renode-rs/issues/74)

An external proposal for a database-first, multi-pass C#→Rust transpiler
platform was reviewed. Full analysis: `docs/architecture-plan-review.md`.

It came from asking why the migration is slow, with the hypothesis that C#
problems and Renode problems had become the same problem. **That hypothesis is
correct and is now measured.**

Of the 4,714 gaps with a named root cause, 69% are the plain C# language and
base class library, 31% are Renode's own types
(`scripts/analysis/classify_gaps.py`, `docs/status/gap_split.json`). See
`docs/decisions/csharp-and-renode-are-two-problems.md`.

### The finding this turns on

The layer boundary is enforced **textually and not behaviourally**.
`check_layering.py` fails a commit if the generic layer names a Renode
construct — but `csharp_core.json` is validated only by whether Renode
peripherals still compile. 69 KB of generic language mappings are governed by
the corpus they are supposed to be independent of, and a C# regression cannot be
told apart from a Renode one because there is only one signal.

That is a validation defect, not a rules-organisation defect.

### Adopted

- #72 — a conformance harness for the language layer, independent of Renode
- #73 — a ratchet on it, so the boundary means something
- #69 — corpus separation (the emitter currently picks a corpus with `LIMIT 1`)
- #70 — a batch-compile ingest mode for many single-file projects
- #71 — the layer check covers one rule file of six
- Reporting the two gap classes separately on the scorecard

### Not adopted

PostgreSQL, the database migration package, a stored annotated-C# artifact, the
marker rename, and the 24-pass framework as a prerequisite. Reasons in the
review doc. In short: the database regenerates from source in about a minute, so
there is nothing to migrate; and no pass framework retires any of the top root
causes.

### The document's central flaw

Unchanged after two passes: its sixteen acceptance criteria are about
documenting, ingesting, caching, timing and compiling. Not one is about behaving
the same as the C#. Judged by them this project is nearly finished; judged by
behaviour it is 3 of 8 peripherals at zero divergence and one file actually
produced by the converter.

An invented `.with_reserved(9, 23)` once survived a 33,164-access trace and
mutation testing, because behaviourally inert wrong code is invisible to every
check of that kind.

### Note on the first review

Two verdicts moved between the first analysis and the second, and both are
recorded in the review doc rather than only the surviving one. The Microsoft C#
test corpus went from "scope expansion, defer" to the highest-value item in the
document; and an objection to the proposal's ownership-inference passes was
withdrawn, because it rejected an idea on the authority of a project rule rather
than on evidence.

## #73 — Ratchet: changing a language rule must re-run the conformance suite

State: **OPEN** · Created: 2026-08-05T14:20:32Z · Labels: gate, rules, transpiler · [View on GitHub](https://github.com/awtoau/awto-renode-rs/issues/73)

The rules are already layered, and the layering is enforced at commit time by
`scripts/validation/check_layering.py`: the generic C# layer
(`scripts/emitter/lang/**`, `rulesdb/rules/csharp_core.json`) may not name a
Renode construct, and the commit fails if it does.

But that boundary is enforced **textually and not behaviourally**.

> `csharp_core.json` is policed for what it may *say*. It is validated only by
> whether Renode peripherals still compile.

A generic C# rule can be changed however one likes, and the only thing that will
object is Renode. So 69 KB of language mappings are governed by the corpus they
are supposed to be independent of, and a C# regression cannot be told apart from
a Renode one because there is only one signal.

The project already has the pattern for fixing this: `compile_check.py` holds a
count of compile-clean modules that may only grow.

### Tasks

- [ ] When `rulesdb/rules/csharp_core.json` or `scripts/emitter/lang/**` changes,
      re-run the conformance suite.
- [ ] The number of tests agreeing may only grow. A fall is a failed commit.
- [ ] Keep the baseline in `docs/status/`, generated, not hand-edited.

### Acceptance

A language rule loosened to make a peripheral emit is caught by tests that know
nothing about Renode.

Depends on #72.

## #72 — Conformance harness: run the C# tests and the translated Rust, compare

State: **OPEN** · Created: 2026-08-05T14:20:14Z · Labels: gate, oracle, transpiler · [View on GitHub](https://github.com/awtoau/awto-renode-rs/issues/72)

**The language layer has no test.**

Every check in this project is structural (paths, layering, generated-file
integrity, ingest completeness) or compile-level. The only behavioural check is
trace replay on 8 peripherals. 283 modules compile clean and **none of them has
ever been executed.**

This matters because 69% of the gaps with a named root cause are plain C#, not
Renode (`scripts/analysis/classify_gaps.py`, `docs/status/gap_split.json`) — so
the majority of what blocks the converter is being discovered and confirmed
through the slowest loop available, a peripheral failing to emit and then
emitting again.

### The instrument

`dotnet/runtime` `src/tests` is a large body of self-contained programs whose
verdict is an integer:

```csharp
[Fact]
public static int TestEntryPoint()
{
    if (!IsNegativeZero(d1)) return 101;
    return 100;
}
```

100 passes, 101 fails. That shape is what makes this cheap: call the method on
both sides and compare two integers. No `Console`, no `string`, no xunit runner,
no firmware, no recorded traces. The C# runtime is the reference, so no expected
outputs are written by hand and every program is self-labelling.

### Tasks

- [ ] `scripts/oracle/conformance.py`: ingest → emit → build → run → compare.
- [ ] Point it at a checkout located by an environment variable, documented in
      `.env.example` (the pattern already used for the other external trees).
- [ ] Report **emitted / agreed / disagreed**, and both denominators, so a
      shrinking attempted-set cannot look like progress.
- [ ] Expect a low emit rate at first, and do not treat that as failure: many of
      these are deliberately exotic (they exist to stress a JIT). The metric is
      agreement among those that emitted, not coverage.

### Acceptance

A single command reports how many C# programs the converter can translate and
how many of those return the same value as the original — the first behavioural
evidence about the language layer that does not involve Renode.

Depends on #69 and #70.

## #70 — Ingest mode for many single-file projects (CSharpCompilation.Create)

State: **OPEN** · Created: 2026-08-05T14:19:51Z · Labels: frontend, transpiler · [View on GitHub](https://github.com/awtoau/awto-renode-rs/issues/70)

`frontend/RenodeIngest/Program.cs` opens one hardcoded project
(`src/Infrastructure/src/Infrastructure.csproj`) through `MSBuildWorkspace`.

A conformance corpus (#72) is the opposite shape: thousands of tiny standalone
projects, one per test. Driving those through MSBuild would be punishing, and

bypassing it with `CSharpCompilation.Create` pending a measurement. This is the
case that makes it necessary rather than optional.

`Walker.cs` does the actual extraction and is reused unchanged; only the loading
front is new.

### Tasks

      BCL, without MSBuild.
- [ ] Reference (or stub) the test attribute so the semantic model stays intact —
      an unresolved attribute degrades type resolution.
- [ ] Measure it against the existing path on the Renode tree, since the design
      note asked for that measurement before the bypass lands.

### Acceptance

A directory of independent `.cs` files ingests into a corpus database with the
same fidelity the project path gives today.

## #69 — The emitter picks its corpus arbitrarily, and the schema assumes one source

State: **OPEN** · Created: 2026-08-05T14:19:42Z · Labels: bug, transpiler, tooling · [View on GitHub](https://github.com/awtoau/awto-renode-rs/issues/69)

`scripts/core/emit.py` selects its corpus with:

```python
run = self.con.execute("SELECT id FROM corpus_run LIMIT 1").fetchone()
```

No `WHERE`, no `ORDER BY`. This is correct today only because exactly one
`corpus_run` row exists. Add a second corpus to that database and the emitter
silently transpiles whichever row SQLite returns first — with no error and no
way to notice from the output.

This blocks the conformance work (#72), and is worth fixing on its own.
Context: #74.

### Tasks

- [ ] Select the corpus explicitly by `config` (and/or an explicit run id), and
      fail loudly when the selection is ambiguous rather than taking the first.
- [ ] Rename `corpus_run.renode_commit` to something source-neutral — a corpus
      that is not Renode cannot honestly populate that column. No migration
      needed: the database regenerates from source, so the schema change is the
      migration.
- [ ] Audit the other consumers for the same `LIMIT 1` assumption.

### Acceptance

Two corpora can coexist without either tool reading the wrong one, and asking
for a corpus that is not present is an error rather than a silent substitution.

## #68 — E0428 "name defined multiple times" — State/Fields collision (fixed) + arm_genericinterruptcontroller's list-register construct

State: **CLOSED** · Created: 2026-08-03T12:38:46Z · Labels: none · [View on GitHub](https://github.com/awtoau/awto-renode-rs/issues/68)

## Context

Discovered via a full 599-module `compile_check.py` run, separate from #64's scope.

## Root cause 1 (32 instances) — FIXED in `99d1b73`

Same State/Fields enum-name collision as #67: a C# nested enum named `State` or `Fields` duplicates the framework's always-hardcoded struct of the same name (E0428, "the name X is defined multiple times"). Fixed by the same corpus-wide rename map described in #67.

**Verified**: `compile_check --ratchet`, E0428 372 → 340 (-32).

## Root cause 2 (340 instances, ~89% in one module) — NOT yet fixed

Concentrated almost entirely in `arm_genericinterruptcontroller` (329 of 340). ## #59 — Unlogged: concepts from the research that never became work

State: **OPEN** · Created: 2026-08-02T09:31:09Z · Labels: research, transpiler · [View on GitHub](https://github.com/awtoau/awto-renode-rs/issues/59)

Concepts surfaced by the four research reports and discussed but **never turned into work**. Recording them so they survive; each is one line here and a paragraph in `docs/research/`.

## Oracle

- **WASM as an oracle (VERT).** Compile C# → WASM, lift WASM → Rust: a correct-by-construction reference that is neither the C# nor our output. C# has a WASM compiler today. **Nobody has done this for C#.** Directly addresses the gap that 8 of 470 compiling modules have ever been executed.
- **Differential fuzzing (FLOURINE).** Register pokes are a small, structured input space — more tractable here than for general C. No test suite required.
- **Held-out validation (Reboot).** Their provided suites pass 100% while held-out tests pass 62–92%; the gap measures overfitting to the tests. We have no held-out set at all.

## Method

- **Feature reduction (Reboot).** Translate a skeleton, validate, add one feature, validate. Beat multi-agent-alone by 6–20 points — the strongest evidence that decomposition beats more model. Our analogue: register layout → computed fields → interrupts, each a complete testable peripheral.
- **The repair loop (Kotlin J2K).** Recompile own output, mechanically patch each diagnostic, remove what the compiler says is unnecessary. J2K survives an admittedly-wrong inference this way. `cargo check` + rule-driven repair is likely a better investment than a cleverer up-front analysis.
- **Compiler shim with fallback (Corrode).** Drop the converter where the compiler goes, fall back on failure, hash-dedupe errors into files. Free coverage metric.
- **Judge/verify by distinct lenses.** Not applied to rules: a rule could be checked by correctness, over-match, and does-it-round-trip separately.

## Ledger and metrics

- **Rule provenance (depyler).** Every rule tagged with the bug that caused it. Ours carry reasoning but nothing links to the failure — the second kind is far harder to rediscover.
- **Declining-LLM-usage metric (depyler).** 200+ → <5 calls per 1000 files. Measures whether the process is *learning*, which instances-per-rule does not.
- **Two marker classes (Bun).** `TODO(port)` for "could not translate" vs `PERF(port)` for "works, slow". Two debts, separately burned down. We have one bucket.
- **A "don't translate" ban list (Bun).** Distinct from `rule_negative`: targets the emitter must not reach for.
- **Failure-signature disclosure ledger (go2cs).** Upgrade the patch count into a named-failure list.
- **`WARNING` tier (Tangible).** "Translated but semantics differ" — we have no such tier, and OrderBy needs one today.

## Corpus

- **265 Robot Framework tests** in Renode's `tests/` are language-neutral and need no translation — only CLI compatibility. Raises the value of oracle tier 5 (#25) considerably.
- **`c2rust known_fn.rs`** (~1000 lines of library models) and **NullAway's `DefaultLibraryModels`** are minable the same way depyler was.

## #57 — GC head-on: Gc<T> to make the port mechanical, a tracer to remove it again

State: **OPEN** · Created: 2026-08-02T09:12:10Z · Labels: decision, transpiler · [View on GitHub](https://github.com/awtoau/awto-renode-rs/issues/57)

**Meet the GC problem head-on rather than route around it**, in two phases:

1. **`Gc<T>` in `csharp-rt`** — so the port is mechanical. A C# reference-typed field becomes `Gc<T>` and the translator stops making an ownership decision per field.
2. **A tracer, later** — so GC objects can be *removed* incrementally, on evidence.

## Why the second half is the clever part

A tracing collector must know what is reachable. That makes it **the dynamic instrumentation this project has repeatedly identified as its strongest missing input**, and never built:

- `c2rust-analyze` instruments and *runs* the program to build a pointer derivation graph, precisely because its static analysis is flow-insensitive
- `pyrs` used MonkeyType the same way — run it, record the types, feed them back
- Bun precomputed a per-field ownership ledger with an `evidence` column and a legal `UNKNOWN`

Our `docs/status/ownership.tsv` is the static version and says `static` in every row. The tracer turns those rows into measured ones: which objects were *actually* shared, *actually* cyclic, *actually* long-lived.

So the GC is not only a porting aid. **It is the measurement device that tells us which fields never needed it.**

## The numbers that justify phase 1

|  | F427 cut | whole tree |
|---|---|---|
| instance fields | 552 | 15,216 |
| object-reference edges | 52 | 1,278 |
| 2-cycles | 7 | **63** (lower bound — only 2-cycles detected) |
| SHARED + BACKREF | 66 | **1,690** |

At 7 cycles, hand-placed `Weak` back-edges are tractable. At 63+, deciding a direction per edge and getting each right is a real burden — and getting one wrong is a leak or a dangling reference, neither of which our oracle can see.

## Prior art, and what it costs

`safe-gc` (Fitzgerald) proves a tracing GC can be built in Rust with `forbid(unsafe_code)`, using an arena plus indices — and its author states plainly it "is not a particularly high-performance garbage collector". `rust-gc` is off-the-shelf and pays in reference-count traffic on every write. Every surveyed design pays its cost in **rooting discipline**, which is the part that could make the port *less* mechanical if the API is wrong.

**So the phase-1 API matters more than the collector.** If using `Gc<T>` is harder than using `Rc<RefCell<T>>`, the porting argument evaporates.

## Relationship to D1 and D2

- **D1** currently says `Rc<RefCell<T>>` with cycles leaked deliberately. This supersedes it if adopted, and D1's reasoning — built once, process exits — is why leaking was acceptable at 7 cycles.
- **D2's arena + typed index handles** is already the named Stage-3 lift, and `safe-gc` shows arena-plus-index is *how you build* a safe collector. The two may be the same work.

## Acceptance

- `Gc<T>` in `csharp-rt` with an API no worse than `Rc<RefCell<T>>` at the use site
- A translation rule mapping reference-typed fields to it, replacing the per-field ownership decision
- The tracer emits per-object evidence in the same shape as `ownership.tsv`, so static and dynamic columns sit side by side
- A demotion path: an object the tracer never saw shared becomes a plain owned value, with the evidence recorded

What is implemented: base fields are **merged** into the derived `State`, base methods become free functions over `(bank, st)`, and **no trait is emitted**.

CLAUDE.md is explicit that this is not allowed:

> The four declared deviations are whole-program decisions; do not make a per-file choice that contradicts one, and **do not silently revisit one — reopen the decision issue.**

I implemented flattening and argued for it as though it were a fresh decision. It was not; it contradicted a decision already recorded.

## What the research said (issue #41)

The decision **survives**, but its stated reason is a non sequitur. The rule bundled three claims:

- **A — base fields flattened into `State`**: correct and forced. RFC 1546 (fields in traits) was postponed in 2018 and its repo has been silent since 2017. Every surveyed system does the physical equivalent.
- **B — base methods as free fns**: correct, but **not because of inheritance**. It is forced by D2's callback type, which has no `self`. The inheritance rule takes credit for a decision D2 already made.
- **C — therefore emit no trait**: **wrong**. "A trait cannot carry the base's fields" argues only for A. A trait does not need fields to carry *methods*, and methods are what dispatch needs.

The agent verified by compiling that an additive dispatch trait works across two peripherals with different `State` types — ~60-90 lines in a new module, changing no existing generated line.

## Also relevant

`merging` versus `embedding` was never considered. IL2CPP embeds the base as a subobject at offset 0; c2rust does the structural equivalent (`struct Derived { parent: Base, ... }`). Embedding avoids name collisions between base and derived fields and makes `base.Reset()` natural, instead of the type-qualified name the current implementation invents.

## The options

1. **Reconcile PLAN.md to the implementation** — record flattening as the decision, and amend line 437. Cheapest; requires stating why composition-plus-trait was rejected.
2. **Reconcile the implementation to PLAN.md** — add the dispatch trait (additive, verified to compile) and reconsider merge-versus-embed.
3. **Re-decide from scratch** on the research in `docs/research/inheritance.md`.

## Acceptance

- PLAN.md line 437 and the implementation agree
- Whichever way it goes is written down as a decision with its reasoning
- The `{base}_{name}` qualified-call convention is confirmed or replaced — note it is **required under a trait model too**, since Rust has no `super` and `Base::reset(self)` re-dispatches

## #55 — Sub-peripheral composition: DMA streams (0.2% on trace replay)

State: **CLOSED** · Created: 2026-08-02T07:34:28Z · Labels: transpiler, code · [View on GitHub](https://github.com/awtoau/awto-renode-rs/issues/55)

`STM32DMA` sits at **0.2%** on trace replay (6,164 divergences over 12,356 accesses) — the worst row in the table.

The cause is structural, not a missing rule. The trace reads `0x40 (StreamFIFOControl+0x1c)`: the real DMA has **8 streams**, each with its own register block. The generated `STM32DMA` module emits only its *own* registers. The per-stream ones live in the separate `Stream` type — which the converter also emits — but nothing composes them, because the `streams` array field is withheld.

**This is the first case of sub-peripheral composition**, and it will not be the last: any peripheral holding an array of register-bearing children has the same shape.

## What is needed

1. A peripheral's `State` may hold an array of child peripherals, each with its own `Bank`
2. Register dispatch routes by offset range to the right child
3. The child's own generated module supplies its layout

## Why it is worth doing

DMA is 12,539 of the ~63,000 accesses currently replayed — the single largest block of unvalidated behaviour.

## Acceptance

- `dma1` and `dma2` accuracy substantially above 0.2% / 9.3%, with the remainder attributed
- The mechanism is general, not DMA-specific — state which other corpus types have the same shape

## #52 — D3/sync — locks are a measurement point: structure preserved, timing NOT certified

State: **OPEN** · Created: 2026-08-01T06:34:08Z · Labels: decision, oracle, transpiler · [View on GitHub](https://github.com/awtoau/awto-renode-rs/issues/52)

Synchronisation is the one construct where **no source-to-source translator can
claim equivalence**, and this one must not pretend to. Timing and interleaving
are properties of the *running* program, not of its text.

## What was done

`lock(x) { ... }` now emits a Mutex guard; a field that is a lock target is
typed `Mutex<T>`, derived from the corpus rather than judged. Every site
carries a `// SYNC(measure)` marker so the uncertified places are greppable.

**42 sites in the F427 cut, 842 across the Renode tree.** Not incidental:
`NVIC.irqs`, `GPIO.sync`, `STM32F1_I2C.updateLock`, `STM32SPI.receiveBuffer`,
`Logger.backendsChangeLock`.

## What is explicitly NOT claimed

**No equivalence is claimed for threading or timing.**

Translated code runs at different rates, so lock hold times, contention
patterns and interleaving all differ from the C#. A translation can preserve
the *structure* of mutual exclusion — which lock protects which data — and
nothing more. Anything stronger would be a claim about two programs' runtime
behaviour that no static translation can support.

## Why the oracle cannot help here

This is the important part.

Tier-2 trace replay feeds **recorded register accesses through a
single-threaded replay**. A threading difference cannot appear in it *by
construction*. So for these 842 sites, "the oracle passes" is not evidence of
anything.

That is the same condition that produced the four bugs which compiled cleanly
and were wrong. Where the oracle is blind, the translation must say so rather
than inherit the confidence of the tests that did run.

## Why D3's "delete the locks" was rejected

PLAN.md D3 proposes removing locks entirely, reasoning that a single-core
guest has nothing to parallelise. That is an argument about **throughput**, not
about **fidelity**, and PLAN.md itself records D3 as:

> "the one place the plan knowingly departs from 'faithful'… It should be
> **re-validated against the Phase-0 profile** rather than assumed."

That re-validation has not happened. Deleting 842 synchronisation points on an
unvalidated performance argument, in the one area our tests cannot observe,
is not a translation.

Preserving the structure costs almost nothing — an uncontended `Mutex` is
close to free — and keeps D3 reversible either way.

## What this issue asks for

1. **Measure, do not assume.** Once peripherals run, measure contention and
   hold times at the marked sites. `// SYNC(measure)` makes them findable.
2. **Decide D3 on evidence**, with a written verdict, and reconcile PLAN.md
   line 444 (`lock(obj)` → "Removed under D3") with what is now emitted.
3. **Build an oracle tier that can see interleaving**, or state plainly that
   we have none. Tier 3 (instruction lockstep) is the candidate; until it
   exists, threading correctness is untested rather than tested-and-passing.
4. **Do not let a green test suite be read as evidence** for these sites.

## Acceptance

- Contention measured at the marked sites on a real workload, with numbers
- A written verdict on D3, and PLAN.md line 444 reconciled
- Either an oracle tier that observes interleaving, or an explicit statement
  in the scorecard that threading is uncertified

## #51 — D5 — Breadth discovers, the cut validates: two rule tiers

State: **OPEN** · Created: 2026-08-01T02:14:05Z · Labels: decision, rules, transpiler · [View on GitHub](https://github.com/awtoau/awto-renode-rs/issues/51)

Amends the rule in CLAUDE.md that read *"breadth must never produce rules,
clusters, coverage numbers, or work items"*.

## Why it is being reopened

That rule was written when the deliverable was stated as "~16k lines of F427
code". The deliverable is now a **general C#-to-Rust transpiler** — Renode is
the corpus that tells us which constructs matter, not the thing being ported.
The rule's premise moved, so the rule needs re-deciding rather than
re-interpreting.

## The evidence

Gap distributions across three scopes agree to within **2.0 percentage points**
(mean absolute difference over shared categories):

| super-category | cut (25 types) | all STM32 (34) | whole tree (569) |
|---|---|---|---|
| type mapping | 41.2% | 37.4% | 53.4% |
| cascades | 48.2% | 46.4% | 34.6% |
| language constructs | 7.8% | 14.9% | 8.3% |

The tree is **22x the code but only 1.3x the operation kinds** (71 → 90). Those
19 extra kinds are not noise for a transpiler:

`SwitchExpression`, `RelationalPattern`, `BinaryPattern`, `NegatedPattern`,
`DiscardPattern`, `ConstantPattern`, `Await`, `Tuple`,
`DeconstructionAssignment`, `CollectionExpression`, …

Modern C# pattern matching, async and tuples — which the cut would never
reveal. The BCL surface is 4.6x larger (531 → 2,420 distinct members).

Cost is not the objection it was assumed to be: 57s, 308 MB, zero converter
crashes across 569 types and 151,548 emitted lines.

## What does NOT change

> **Breadth can prove a rule EMITS. It can never prove the output is RIGHT.**

The oracle is trace replay and the traces are of the cut. A rule matched a
thousand times outside it has produced plausible output a thousand times —
precisely how the invented `.with_reserved(9, 23)` survived a 33,000-access
trace and 81% mutation testing. Behaviourally inert wrong code is invisible to
tests.

## The decision

Two validated tiers, enforced by schema triggers rather than by review:

| tier | threshold | guarantee |
|---|---|---|
| `general` | ≥3 instances **anywhere**, breadth included | emits on real code; correctness unknown |
| `committed` | ≥3 instances **in the cut**, each oracle-backed | the output is right |

- `rule_commit_threshold` now counts only instances whose
  `corpus_run.config <> 'breadth'`.
- `rule_general_threshold` added, so `general` still cannot be claimed from a
  single site — one site is a patch, whatever corpus it came from.
- Metrics report the tiers separately. Coverage and instances-per-rule continue
  to mean *validated*, never *emitted*.

## The risk being accepted

Effort may go into constructs used only by peripherals we never verify
(`decimal`: 249 blocked gaps, `nint`: 123 — both nearly absent from the cut).
That is accepted deliberately: they are real C#, and the transpiler is the
deliverable. The mitigation is that they can only ever reach `general`, so they
cannot inflate any number that claims correctness.

## Reversal criterion

If `general` rules start outnumbering `committed` ones, the project has drifted
into emitting rather than translating, and this decision should be revisited.
That ratio is the thing to watch.

## #37 — R3b — Revisit the coverage metric: bare leaves are not rule failures

State: **OPEN** · Created: 2026-07-31T02:59:52Z · Labels: phase-1, gate, rules · [View on GitHub](https://github.com/awtoau/awto-renode-rs/issues/37)

Follow-up to #16 (R3). **Does not block R6.**

The census gate measured **74.4% of AST nodes coverable by 653 patterns** against an ≥80% threshold invented while writing the script. We proceeded on the collapse reading (653 patterns is "hundreds, not tens of thousands", which is what PLAN.md asked), but the coverage metric should be corrected rather than quietly dropped.

### The problem with the current metric

The uncovered 25.6% is dominated by bare leaf references:

| kind | uncovered |
|---|---:|
| `ParameterReference` | 1,389 |
| `Literal` | 784 |
| `InstanceReference` | 709 |
| `LocalReference` | 620 |
| `FieldReference` | 311 |

These are **individual identifiers**. No rule system would emit a rule for a bare parameter reference — they are the *operands* a rule consumes, not constructs a rule matches. Counting them as coverage failures measures the wrong thing.

### Options

1. **Exclude sub-rule-sized nodes from the denominator.** Coverage becomes "of the nodes a rule could plausibly match, what fraction is covered". Cleanest, but needs a defensible definition of "plausibly matchable".
2. **Weight by node, but count a covered parent as covering its leaf operands.** Arguably already true — a matched `.WithFlag(lit, out field, lit)` does consume its literals. Check whether the greedy cover is failing to credit these.
3. **Report both** and stop treating one number as the gate.

Option 2 deserves checking first: if the greedy cover descends into a subtree it could have matched at a higher level, the leaves get counted as uncovered when they are not.

### Do not

Re-tune the fingerprint to raise the number. Every fingerprint fix so far was justified by an independent artifact (compiler-inserted nodes, extension-method receivers); adjusting further to cross a threshold would be gaming the gate.

## #36 — R7 — Parallel conversion harness: saturate 31 threads, deterministically

State: **OPEN** · Created: 2026-07-31T00:17:11Z · Labels: phase-1, rules, perf · [View on GitHub](https://github.com/awtoau/awto-renode-rs/issues/36)

Blocked by #R1. **Cross-cutting — every stage must satisfy this, so it is
specified once here rather than rediscovered per stage.**

Conversion is re-run constantly during rule development, so its wall-clock *is*
the iteration speed. A single-threaded stage is a defect with a recorded reason,
not an acceptable default.

**Machine:** i9-14900K — 24 physical cores (8 P-cores hyperthreaded = 16 threads,
plus 16 E-cores), **31 usable threads**, 36 MiB shared L3, 62 GB RAM. It is
**heterogeneous**, and naive thread pools schedule it badly: a uniform-core
assumption puts a critical-path task on an E-core and stalls the stage behind it.

### What parallelises

| Stage | Shape |
|---|---|
| Roslyn compilation load | **Serial, unavoidable** — cross-file resolution needs the whole `Compilation`. Measure it; this is the Amdahl floor |
| `IOperation` walk | Per file. `SemanticModel` is safe for concurrent reads once the compilation exists |
| DB write | Per-worker SQLite → one merge. WAL mode. Never 31 writers on one file |
| Metrics, fingerprints | Per method — pure functions of one subtree |
| Purity fixpoint | Parallel worklist per iteration |
| **Rule application / emission** | **Fully parallel — see below** |
| Rule validation | Per match |
| LLM cluster calls | Per cluster; batch against rate limits |

### The emission insight

The leaves-first queue orders **rule discovery**, not rule *application*. Once a
rule is committed, applying it is a pure function
`(operation subtree, rule set) → Rust` with no shared state and no dependence on
call-graph position. The whole corpus therefore emits in parallel; only the
discovery loop is ordered. Conflating the two would serialise the most expensive
stage for no reason.

### Tasks

- **Determinism check in CI: run the pipeline at `-j1` and `-j31` and diff.**
  Byte-identical or fail. Without this the differential oracle is worthless,
  because every diff against the C# reference becomes scheduling noise. Requires:
  no timestamps or paths in generated output, content-derived stable IDs, sorted
  writes, no hash-map iteration-order dependence.
- Work-stealing scheduler, not static partitioning — E-cores retire short tasks
  at roughly half a P-core's rate, so static splits leave P-cores idle.
- Content-addressed cache keyed on `(subtree hash, rule-set hash)`, so a rule
  change recomputes only what changed.
- Per-stage core-utilisation telemetry into `progress_snapshot`, tracked
  alongside instances-per-rule.
- Measure the serial fraction and state the resulting Amdahl ceiling honestly.

### On forking Roslyn

Available if needed, but **it should be a measured decision, not an assumption** —
and it is probably unnecessary, since the parallelism above works through the
public API. Two cheaper moves come first:

- **Bypass `MSBuildWorkspace`** — build `CSharpCompilation.Create` directly with
  explicit references. Faster, more deterministic, drops a slow and occasionally
  flaky dependency.
- **Cache the compilation** — the serial load only needs to re-run when the
  corpus commit changes.

Fork only if a measured bottleneck traces to something the public API cannot
express, and record that measurement in this issue before forking anything.

**Exit** — every stage reports core utilisation; the `-j1` vs `-j31` determinism
check is green in CI; the serial fraction and Amdahl ceiling are documented.

## #35 — R6 — The rule engine: match, emit, validate against ALL occurrences

State: **OPEN** · Created: 2026-07-31T00:13:43Z · Labels: phase-3, rules · [View on GitHub](https://github.com/awtoau/awto-renode-rs/issues/35)

Blocked by #R3 and #12. **This is the machine the whole project rests on.**

The loop, and every step is mechanical:

```
take next method from translation_order (leaves first, simplest first)
  → match committed rules against its operation tree
      ├─ full cover → emit Rust, run its generated test
      └─ residue   → cluster the unmatched subtree with similar misses
                     corpus-wide
                   → ONE LLM call per cluster proposes a GENERAL rule
                   → query the corpus for ALL matches of that rule
                   → validate each match against the oracle
                   → ≥3 validated instances?  commit the rule
                       else                    record as a `patch`
```

**Tasks**
- Matcher over the `operation` tree; rules are patterns plus constraints, not
  regexes over text.
- `rule_match` populated by **querying the corpus**, never by hand. This is the
  operation that was unavailable to `linux-rs` and the reason its rules stayed
  one-offs.
- Enforce the commit threshold in the tool, not in review:
  `status='committed'` is unreachable while
  `COUNT(rule_instance) < min_instances_required` (default 3).
- `rule_negative` — shapes the rule must *not* match — to guard against
  over-generalisation. A rule that matches too much is worse than one that
  matches too little, because the oracle may not catch it.
- `requires_human_gate` forced on for semantics-bearing families: anything
  touching time, IRQ delivery ordering, or the D1/D3 decisions. Those get human
  review **regardless of oracle tier**, because no automated tier catches a wrong
  ordering mapping.
- LLM invocation is **per cluster**. A per-function invocation path must not
  exist in the tool.

### Design constraint: whole-type transformation, from the start

**Rules must match and emit at type and member granularity, not only over
`operation` subtrees.** Statement-level substitution is enough for faithful
translation and not enough for anything after it.

Why it cannot be deferred: changing an object model — inheritance to composition,
GC graph to indexed storage, or leaving Renode's model behind entirely — is not a
local rewrite over expressions. Retrofitting whole-type restructuring onto a
statement-substitution engine is an engine rewrite. The schema already permits it
(`operation` → `method` → `member` → `type`); the emitter must be built for it.

This is what keeps D1–D4 reversible and makes rule-set variants comparable — see
"The codebase is a build artifact" in
[docs/rulesdb-design.md](rulesdb-design.md).

**Cost model this exists to deliver:** ~200–400 LLM invocations for the corpus
rather than ~2,000, and the committed rules carry forward to the other 419
DSL-style peripheral files (208,580 lines) at no further LLM cost.

**The larger payoff:** with rules as the source code, architectural decisions
become re-runs rather than rewrites, and alternative rule sets can be built and
benchmarked against the same oracle instead of argued about.

**Exit** — engine runs the queue end to end; threshold enforced mechanically;
`instances_per_rule` reported per run.

## #12 — 8 — Implement the register DSL in Rust

the C# implementation.

## #9 — 5 — DECISION D3: threading model

State: **OPEN** · Created: 2026-07-31T00:01:27Z · Labels: phase-0, decision · [View on GitHub](https://github.com/awtoau/awto-renode-rs/issues/9)

**The decision most worth challenging.** Written verdict required.

Blocked by #P1.

Renode is multithreaded: ~2k of the 6,277-line time framework is thread
coordination (`TimeSourceBase` 1041, `TimeHandle` 935, plus the master/slave
sources) — and that machinery sits **on the hot path**, since `SyncTime` →
`ReportProgress` walks it on every timer register poll.

The proposal is **single-threaded within one machine**, and the argument is now
performance-led rather than simplicity-led:

1. **Intra-instance parallelism does not pay for a single-core MCU.** There is
   one CPU. Peripherals could tick on other threads, but every interaction point
   needs synchronisation and a polling loop drives that rate through the roof.
   QEMU's MTTCG parallelises *guest cores*, not guest peripherals, for exactly
   this reason — and here there is one guest core.
2. **Removing the thread coordination is itself an optimisation.**
   Single-threaded, `ReportProgress` collapses to `virtual_time += delta` plus a
   deadline comparison.
3. Determinism is the product and is easier to guarantee without threads.

**The parallelism that pays is N independent instances** — the CLI test suite
across 16 cores. That needs the machine `Send` (which D1's `Rc` blocks and D2's
arena permits) or process isolation. Processes work today; note the tension and
do not close it off.

**Tasks**
- Take the time-framework share of the profile from #P1. If it is small, this
  decision matters less than assumed and should say so.
- Establish what, if anything, in the F427 boot path depends on genuinely
  concurrent execution rather than interleaving the time framework already
  serialises.
- Check whether tlib's execution model imposes a threading requirement of its own.
- Decide the N-instance story: threads (needs `Send`, implies the D1 arena) or
  processes (works now).
- Write the verdict, including what evidence would reverse it.

**Exit** — `docs/decision-d3.md` committed.

## #8 — 4 — DECISION D1/D2: object graph and register field representation

State: **OPEN** · Created: 2026-07-31T00:01:25Z · Labels: phase-0, decision · [View on GitHub](https://github.com/awtoau/awto-renode-rs/issues/8)

Written verdict required. See PLAN.md "The four declared deviations".

Blocked by #P1 — this decision is made against the profile, not ahead of it.

**D1 (coarse object graph)** — proposal is `Rc<RefCell<T>>` with cycles leaked
(correct: the machine is built once and the process exits). One indirection and
one borrow check per MMIO access, not per field. Keeps the translation literal.
Cost: it makes a machine `!Send`, so N-instance test parallelism needs processes
rather than threads.

**D2 (register fields)** — proposal is **`Cell` in a contiguous arena with typed
index handles**, *not* `Rc<RefCell<_>>` per field. Register fields are all `Copy`
scalars (`ulong`, `bool`, small enums), which is exactly `Cell`'s use case. RCC
alone defines ~240 fields; one heap allocation each, with 16 B of refcounts and
an 8 B borrow flag apiece scattered across the heap, is the difference between a
polling loop living in L1 and one missing cache on every read.

This costs nothing in faithfulness — the DSL is the abstraction boundary, so
translated peripheral code reads identically either way — and it removes the
borrow-panic hazard entirely for the most numerous object in the system.

**The remaining real work is the borrow discipline for D1.** `RefCell` panics on
re-entrant borrow; the exposure is peripheral → sysbus → peripheral (DMA reading
memory through the bus while the DMA peripheral is itself borrowed). A panic
there is not necessarily a C# bug — it may be legitimate re-entrancy C# tolerates.

**Tasks**
- Take the D2 layout verdict from #P1's head-to-head measurement.
- Enumerate the re-entrant paths in the F427 corpus by inspection: which
  peripherals call back into the bus, and from where.
- Propose and write down the discipline (candidate: never hold a borrow across a
  bus call; bus calls take `&self` and re-borrow internally).
- Record the D1 arena lift (`PeripheralId` indices, machine becomes `Send`) as
  the named Stage-3 successor, #23 — deferred, not rejected.

**Exit** — `docs/decision-d1-d2.md` committed with the verdict, the enumerated
re-entrant paths, and the discipline.

## #5 — P3 — [deferred research] Running tlib through the linux-rs C→Rust pipeline

State: **OPEN** · Created: 2026-07-31T00:01:21Z · Labels: deferred, research · [View on GitHub](https://github.com/awtoau/awto-renode-rs/issues/5)

> **Not scheduled. Does not block any phase.** Same status as #P2 — and note
> this is C→Rust work, which does not reduce the C# surface and therefore does
> not serve this project's stated motivation.

Logged because the idea is sound and the reuse is real: `linux-rs` already has a
working C→Rust pipeline and a hardened `awtoau/c2rust` fork, tlib is 227k lines
of **C** (c2rust's actual domain, unlike the C# side), and translating it would
remove the FFI boundary entirely.

**Recommendation: not as the first target.** Reasoning below; the issue exists so
the decision is recorded rather than assumed, and so the stepping-stone variant
does not get lost.

### Prior art (searched 2026-07-31, needs a fuller dig)

- **`zevorn/tcg-rs`** — "Rust for QEMU TCG", Rust, 31★, active (updated
  2026-07-22).
- **`qemu-rs/qemu-rs`** — "QEMU for Rust, and Rust for QEMU", 103★, active
  (2026-07-23).
- **QEMU upstream has official Rust support** — `wiki.qemu.org/RustInQemu`,
  `qemu.org/docs/master/devel/rust.html`. Hand-written Rust *device models*, not
  translation: the exact Rust-for-Linux analogue, and the same "no translation by
  policy" shape.
- **No c2rust-on-QEMU work found** — `gh search repos "c2rust qemu"` returns
  empty.

So: partially done, actively moving, and the specific thing proposed here
(mechanical translation) is unclaimed. **The fuller survey is a task below, not a
settled result — 31 stars is not an assessment.**

### Why not first

1. **c2rust hits its hardest cases in TCG.** Computed goto for the dispatch loop,
   `setjmp`/`longjmp` for `cpu_loop_exit` unwinding, inline asm, function-pointer
   tables, and runtime host-code generation. `setjmp`/`longjmp` in particular has
   no clean Rust equivalent and is a known c2rust weak point.
2. **You would get a JIT, in Rust.** The generated-code path is irreducibly
   `unsafe` — it emits bytes and jumps to them — so there is no safety win there,
   and it stays untestable per-instruction. **That is precisely the complaint that
   motivated #P2.** Translating the JIT preserves the defect.
3. **It does not serve either stated motivation.** The C# maintenance burden is
   unaffected — tlib is C, not C#. And if #P1 shows the CPU is not the
   bottleneck, translating it buys nothing on performance either.
4. **It does not test the project's central risk**, which is whether the rule
   thesis holds for C#. Months spent here and a failed C# gate leaves a Rust QEMU
   fork and no answer.

### The variant that *is* attractive

**c2rust tlib as a stepping stone to deleting it.** Translate faithfully → the
build is now one language → then replace the JIT with a testable interpreter
incrementally, function by function, using the c2rust output as the differential
baseline. That is exactly the linux-rs method applied here, and it is coherent in
a way "translate and stop" is not.

This merges with #P2: they are the same decision. #P2 asks "what should the CPU
be"; this asks "how do we get there". If the answer to #P2 is "a testable
interpreter", this is one credible route to it.

### Tasks

- Do the proper prior-art dig: `zevorn/tcg-rs` (what does it actually cover —
  the TCG IR, a backend, a whole emulator?), `qemu-rs`, QEMU's upstream Rust
  effort, and search beyond GitHub (GitLab, Codeberg, sr.ht, grep.app).
- Assess c2rust's actual behaviour on tlib's hard constructs — take `arch/arm`
  and *try it*, using the `awtoau/c2rust` fork. A one-day experiment beats
  argument, and any failures are useful upstream to `linux-rs` regardless.
- Cost the stepping-stone variant against a from-scratch interpreter (#P2).
- Feed any c2rust gaps found back to `awtoau/c2rust` as evidence-based issues —
  that is the fork's stated purpose and the benefit compounds for `linux-rs`.

### Exit

Merged into `docs/cpu-options.md` (#P2) as a costed route, or recorded as
rejected with reasons.

## #4 — P2 — [deferred research] Replacing tlib: 2008-vintage QEMU with no tests

State: **OPEN** · Created: 2026-07-31T00:01:20Z · Labels: deferred, research · [View on GitHub](https://github.com/awtoau/awto-renode-rs/issues/4)

> **Not scheduled. Does not block any phase. Nobody works on this during
> Phases 0–4.** Logged so the evidence is not lost and the decision is not made
> by default. The scoped project is Renode's **ARM-only C# subset**; tlib is C,
> stays behind FFI, and is not in scope.

Phase 1 FFIs to tlib unchanged, deliberately —
keeping the CPU identical on both sides is what makes the tier-3 lockstep oracle
exact. This issue exists because the long-term answer is probably different, and
the decision should be evidence-led rather than inherited.

### The evidence

| | |
|---|---|
| Lineage | ARM translator carries Fabrice Bellard (2003, 2008), CodeSourcery (2005–2007) and OpenedHand (2007) copyrights — the QEMU 0.9/1.0-era TCG |
| Size | 19,157 lines of ARM translation; 227,771 lines of C in tlib overall |
| Tests | **One test file in the entire tree** — `hash-table-store-test.c`, which tests a hash table. There is no instruction-level test infrastructure at all |

The structure is the problem, not just the age. TCG is a JIT: instruction
semantics are expressed as code that *emits* host code. You cannot unit-test
"does `UMLAL` set the flags correctly" without running generated machine code, so
in practice nobody does, and the model's correctness rests on it having been
exercised by real guests rather than on any test.

### The decisive question, and it depends on #P1

**Is instruction dispatch even on the critical path?**

If #P1 shows the cost is dominated by the MMIO path — managed boundary, time
sync, register dispatch — and not by instruction execution, then the JIT is
buying very little and costing a great deal in opacity. Renode currently manages
~50 MIPS *with* a JIT. A straightforward Thumb-2 interpreter in Rust is
plausibly in the same range on a modern host for this ISA, because Cortex-M is
small and regular.

If that holds, the trade is: **give up JIT throughput that is not the bottleneck,
and buy per-instruction testability** — one pure function per instruction, each
directly unit-testable, which is the thing tlib structurally cannot offer.

### Tasks

- Take the instruction-dispatch share of the profile from #P1. If it is small,
  say so plainly — that single number decides most of this.
- Quantify the divergence from upstream QEMU: what has Renode's fork changed,
  and what upstream TCG fixes since ~2010 has it never received? (Relevant to
  correctness, not just tidiness.)
- Survey the options, honestly and without assuming the answer:
  - A hand-written Rust Thumb-2/Cortex-M interpreter — most testable, unknown
    throughput, moderate build.
  - Existing Rust ARM emulation crates — establish what actually exists and is
    maintained rather than assuming.
  - Unicorn Engine — note it is itself QEMU-derived, so it inherits the same
    structural testability problem.
  - **Generated from a formal spec** — ARM publishes a machine-readable
    architecture specification (ASL), and Sail has been used to derive executable
    ARM models from it. A generated model is testable *against the vendor's own
    definition* rather than against someone's reading of the manual. Highest
    ceiling, highest unknown; worth costing rather than dismissing.
  - Rebasing onto modern upstream TCG — cheapest, fixes the age, fixes nothing
    about testability.
- **Design the validation strategy, which is unusually strong here.** We have the
  physical STM32F427 and existing SWD tooling. Random-instruction differential
  testing against real silicon — generate sequences, run on hardware, run on the
  model, diff registers and flags — is the gold-standard CPU validation method,
  and it is available to this project in a way it is not to most. This is worth
  specifying **regardless of which CPU option wins**, including if the answer is
  "keep tlib": it would be the first real test coverage tlib has ever had.

### Exit

`docs/cpu-options.md` with the #P1 dispatch share, the divergence assessment, a
costed option comparison, and a recommendation. A recommendation of "keep tlib,
but build the hardware-differential test harness" is a legitimate and possibly
the correct outcome.

## #3 — P1 — GATE: performance spike, before the design is locked

State: **OPEN** · Created: 2026-07-31T00:01:18Z · Labels: phase-0, gate, perf · [View on GitHub](https://github.com/awtoau/awto-renode-rs/issues/3)

**A genuine stop point, and the first real work after #1.**

Performance is a primary motivation (see PLAN.md, "Performance is a first-class
goal"), and the plan currently *assumes* Rust wins on the MMIO path. That
assumption must be tested before the architecture is committed, because a
negative result changes what this project is.

**The case to profile.** The firmware's LSI measurement spins on `TIM5->SR` up to
500,000 times per edge across 130 edges — order 65M MMIO reads, ~30 ms on
hardware, **~27 s under C# Renode**. Traced through the source, each poll goes:

```
STM32_Timer.cs:198  → cpu.SyncTime()
TranslationCPU.cs   → TlibGetExecutedInstructions()   [P/Invoke, managed↔native]
                    → ReportProgress(...)             [multithreaded TimeHandle
                                                       state machine]
```

The sync is semantically required — the counter depends on elapsed virtual time,
which only advances when the CPU reports progress. The question is entirely how
much the *implementation* costs.

**Tasks**
- Profile C# Renode over the LSI boot (`perf` and/or `dotnet-trace`). Produce the
  split: tlib execution vs managed boundary vs time framework vs address decode
  vs register dispatch vs GC. **This number does not currently exist and every
  performance claim in PLAN.md depends on it.**
- Build a throwaway Rust prototype of just the MMIO path: tlib → Rust callback →
  one peripheral → one register field. No DSL, no rules, no correctness — just
  the hot path.
- Microbenchmark both: N million reads of one timer register. Report
  accesses/sec.
- Compare the two D2 candidate layouts head to head in the prototype:
  `Rc<RefCell<_>>` per field versus `Cell` in a contiguous arena. Measure, do not
  assume — the claimed difference is cache behaviour and it should show up as one.
- Establish the tracked metrics: MMIO accesses/sec, instructions/sec, and the
  MMIO:instruction ratio.

**Exit** — `docs/perf-spike.md` with the C# profile breakdown, the Rust
prototype numbers, the D2 layout comparison, and a verdict.

- **Pass** — the Rust MMIO path is materially faster and the profile identifies
  where. Proceed; the numbers become the Phase-4 baseline.
- **Fail** — the win is marginal. The performance motivation evaporates and this
  becomes a safety-only project (still defensible on the two null-handling
  defects, but a much weaker case). **That verdict must be allowed to stand.**
