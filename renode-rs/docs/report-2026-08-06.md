## What landed today

**#63 — utility types** (`c050e6e`, `20b2992` on `reframe-plain-english`):
`BitHelper`, `Misc`, `DebugHelper` and similar pure-static C# classes now emit
as real Rust modules, with cross-module call resolution so peripheral code can
call into them instead of withholding. Two escaping bugs fixed on the way:
control characters (ESC, BEL) in string/char literals were unescaped in two
separate rendering paths — `emitter/lang/expressions.py`'s `literal()` (the
`Literal`-operation path) and `emitter/lang/const_field.py`'s
`constant_field()` (the `FieldReference`-to-a-`const`-field path, which
bypassed `literal()` entirely). A third bug — duplicate `pub mod` declarations
for 4 static-extension types selected by both `owners()` and the new
`utility_owners()` — was fixed in `register_owners.py`. #63 stays open: its own
"drop out of the ranking" acceptance bar isn't met yet.

**#64–#68 closed**, each with module-level proof against its own stated

**Two new defect classes found and filed** as
[#75](https://github.com/awtoau/awto-renode-rs/issues/75), from source
inspection during that verification, not from any issue's original scope:

1. A `/* GAP: ... */` comment spliced into a position where Rust syntax
   requires a real expression — `if !/* GAP: base-class call */ {` leaves `!`
   negating nothing. Same shape in `arm.rs` and `sifive_uart.rs`; related
   parse-error variants (format-arg-count mismatches, "expected a pattern,
   found an expression") across ~15 modules total. Generic emitter bug: a gap
   in expression position should withhold the enclosing statement, not
   interpolate.
2. Duplicate synthesized names within one module — `isp1761.rs` has six
   `pub const IMPLICIT: u64 = ...;` at different values, no disambiguation.
   11 E0428 instances across 6 modules total.

The platform floor almost doubling is the number that actually matters here:
the GPIO/EXTI cross-module call resolution `BitHelper.GetValueFromBitsArray`
that #63's fix enabled reaches platform-critical peripherals already on the
`.repl`, not just the newly-added utility modules. `floor.json` and
`STATUS.md` had gone stale (still reporting 283/173/27 after the ratchet
already stood at 617) until refreshed and committed today (`754d7a8`).

143 errors remain across 70 modules; #75 above accounts for a portion of
those, the rest are unclassified individual defects (`lsm330_accelerometer`
and `lsm330_gyroscope` at 7 errors each are the current worst offenders).
