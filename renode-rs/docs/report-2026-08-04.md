**These numbers moved during today's review, and not from new emitter work.**
`docs/status/floor.json` had gone stale relative to the rest of the repo — it
was last regenerated well before several already-landed fixes, and before
`register_owners.py`'s content-based selector (which replaced a NAME-based
query that dropped any type defining its registers in a constructor) had ever
been re-run through `floor_census.py`. `compile_check.py`'s real emission path
already used the fixed selector; `floor_census.py`'s own census had a second,
forgotten copy of the exact query the fix replaced, so it kept reporting the
old defect after it no longer existed. Fixed today (`floor_census.py`,
`emitted_types`/`why_not_emitted` now call `register_owners.owners`/
`candidates` instead of re-deriving the same answer by name) and reran from
scratch: platform floor moved 23→27, clean-and-drivable 109/560→173/599.
**Lesson: re-run a census before trusting it as "current state" — a stale
artifact reads exactly like real regression-free ground.**

## Why the remaining platform peripherals aren't on the floor

`docs/status/floor.json` → `platform_not_emitted` (15 of 65), by cause:

| cause | peripherals |
|---|---|
| no register-defining member at all (`MappedMemory`/bus peripherals, or a switch-on-address peripheral with no DSL) | `sram`, `rom1`, `rom2`, `ccmram`, `bkpsram`, `fsmcBank1`, `ethernet`, `bitbandPeripherals`, `bitbandSram`, `can1`, `can2` |
| `.repl` name doesn't map to a real C# class | `crc_f4`, `flash`, `flash_ctrl`, `master`(can1) |

`rcc`, `rng`, `rtc` are no longer in this list — `rcc` is emitted and drivable
but not yet *clean* (8 `no field UNKNOWN on type Fields` errors, a known,
separately tracked gap unrelated to selection; see
[docs/issues/sel-2-unresolved-field-emits-the-identifier-UNKNOWN.md](issues/sel-2-unresolved-field-emits-the-identifier-UNKNOWN.md)).
`rng` and `rtc` are now both clean, drivable, and on the floor.

The remaining `MappedMemory`/bus-peripheral bucket (11 peripherals) needs a new
converter code path, not a rule — those types have no register-DSL member at
all. The `.repl`-name bucket (4 peripherals) is a naming/mapping problem in the
platform description, unrelated to emission capability.

## Biggest issues, ranked

1. **Stale reporting can look exactly like a real regression or a real gap** —
   today's floor.json was itself the biggest single finding: two forgotten
   duplicate queries in `floor_census.py` made three already-fixable
   peripherals (rcc, rng, rtc) look like a live selector limitation. Fixed;
   the census now shares one selector with the real emission pipeline. Worth
   auditing other analysis scripts for the same kind of second-source-of-truth
   duplication.
2. **11 platform peripherals are structurally invisible** to the register-DSL
   selector (`MappedMemory`/bus peripherals, or address-switched peripherals
   with no DSL, like `STMCAN`) — needs a new converter code path.
3. **4 more are `.repl`-to-C#-class mapping failures**, unrelated to emission
   capability.
4. **Gaps are systemic, not per-file**: 2 root categories
   (constructor-statement-not-initialiser, "other") are 27.8% of everything.
5. **Correctness lags compilation**: only 3/8 oracle-traced peripherals replay
   at 0 divergence; adc1 alone has 1,192 (see report-2026-08-03.md for the
   full table — unchanged today).
6. **The converter's core thesis has one real data point**: only
   `uart_registers.rs` is both generated and byte-enforced against generator
   output; UART behavior and all of GPIO remain hand-written.
7. **Threading uncertified**: 56 lock sites in the corpus, 0 in emitted Rust.
